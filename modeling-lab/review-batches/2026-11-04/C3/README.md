## 方法与损失
- 仅同材质、同属性布局合批；没有跨材质盲合UV，没有改写UV、法线或材质系数。
- 平移节点烘入顶点，世界坐标6位小数有向三角＋材质＋原UV＋原法线多重集相等。未声称浮点逐字节几何无损；原字节可由baseline恢复。
- 9张自制PBR纹理分别缩至256或128。法线图缩采样后重新单位化。当前basecolor采用Pillow Lanczos编码色值重采样，未实现线性色彩重采样；这属于明确的视觉有损候选，不能叫无损去重。
- 静态合批失去单件节点驱动/选择能力，轮、绳、容器不能再单独动画。动画或交互版继续使用原源模型，未来须将可动件从批次剥离。
- 细小木纹/瓦纹/法线起伏会变弱。CPU对照可见整体轮廓、井口、木架位置保持，但480px静态图不足以证明实时运动无闪烁或所有距离均无损。
- 建议先试256px作为中远景默认候选，128px作为更远景候选。试验起点：物体屏幕高度分别不超过240px/120px；不是已验收阈值。不指定固定米数，因为镜头FOV、分辨率与缩放未知。近景继续原LOD0。尚未改城市切换逻辑。

## 证据
qa/metrics.json绑定实际GLB SHA与指标；qa/topology.json按原始壳体分区验证，四候选各壳闭合、有向边一致、无退化、无有向重复、正有向体积；qa/bore-rays.json各5条井口有限采样均未遇到假地板。不是全体构件穿插归零结论。原来的支承嵌接、接缝和运动限制不因合批自动解决。
qa/*mapping.json保存每个原节点到新批次的顶点/索引范围与原平移，可定位回退。几何不变测试与有限遮挡测试支持没有引入新形体，但不能代替引擎动态闪烁验收。
12张480px CPU Cycles静态图，固定灯光、镜头、24 samples、seed0；汇总为qa/well-lod-comparison.png。它们不代表GPU、手机或Unity/Godot验收。
qa/invalid-inputs.json保留未测试分辨率被拒绝的检查；生成器只允许静态、平移、单场景、独立mesh、三角模式，旋转/缩放、动画/蒙皮等输入必须拒绝，不静默丢失。

## 复现
Python3 + numpy + Pillow：运行source/optimize.py，source/check.py，source/topology.py，source/ray-check.py；Blender4.3 CPU运行source/render.py，再运行source/contact_sheet.py。原始资源在baseline/assets，无需网络。配置仅A/B×128/256，有限样本不证明所有模型都安全。

## 采用判断
256优先试用，128保留对照，不自动替换；不做纹理图集打包，因为本轮已显著减少载荷，图集会增加UV接缝、复用复杂度，需要另外验收。下一步由前端/引擎按实际屏幕尺寸验证切换、动态稳定性、可动部件需求后选择。公开前须单独净化托管投影，本完整原件研究包不直接整体公开。
