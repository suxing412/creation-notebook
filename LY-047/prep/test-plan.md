这份计划按「本项验收」三条写成可执行检查。正式制作时直接跑；这里每条都写明：正例、负例、容差、要绑定的 SHA。

先选路线，由 LY-010 的决策表决定：

- **路线 R**：示范院是 B 或 B2，原位复用院内的棚和储藏屋。
- **路线 W**：示范院是 A2 C02-010，在院内安装 workshed。

两条路线共用 T0、T3、T5、T6；T1、T2、T4 按路线分别跑。

## T1 支承（验收「支持可验证」）

脚本：`measure_ly047.py`，看 `inplace.*.bottom_*`、`post_on_plinth_gap_m`、`city_instances`、`a2_install_option.city_ground_under_posts_with_y_offset_0.2`。

**路线 R：**

- 所选院所有落地的棚件和储藏件底点（B 40 个、B2 40 个），竖直射线打到城景地面。
  - 通过：无地面 0；|间隙| ≤ 5 mm；埋入（< −5 mm）为 0。
  - 4 根柱坐在柱础上，间隙 |g| ≤ 1e−4 m。
  - 储藏屋地台和踏步的底面在 0.200 ± 1e−4。
- 基线实测：17 院全部通过，间隙在 −3e−9 到 0 之间。

**路线 W：**

- 安装后，6 根柱、12 个底点，打到 C02-010 下的 ground-south。
  - 通过：同上，并且承托来源只有 ground-south 一个文件。
- 负例 N1（selftest 已有）：不做 y +0.200 平移，必须检出间隙 −0.200（埋入）。

**两条路线共同的负例：**

- 默认视图（地面 `initial:false`）下必须报「无地面」。这一条用来证明检查器不会把「地面没加载」当成通过。修好以后再测一次，结论只能写「加载配置修正后通过」，不能写「原本就有支承」。

## T2 取放空间（验收「取放空间可验证」）

C 参数：

| 参数 | 值 |
|---|---|
| 身体带 | 地面以上 0.25–1.90 m |
| 空手半径 | r 0.30 m |
| 带货半径 | r 0.45 m |
| 取放距离 | ≤ 0.70 m |
| 操作带深度 | 0.90 m |
| 栅格 | 0.05 m |

**路线 R：**

- 每个箱子和台案至少有 1 个面，在空手条件下从院门可达，距离 ≤ 0.70 m。
  - 基线：四个面都在 0.325–0.375 m。
- 带货可达的面要逐个列出。朝台案那一面（间距 0.5 m）带货不可达，必须写进使用限制。
  - 基线：B 每个箱子 3 个面可达；B2 每个箱子 3 个面可达。
- 储物箱上方净空 ≥ 1.80 m（基线 1.91 m）；梁底 ≥ 2.10 m（基线 2.15 m）。
- 储藏屋：
  - 门洞净宽 ≥ 0.9 m（基线 1.66 m），净高 ≥ 1.9 m（基线 2.24 m）；
  - 屋内可达面积 > 0（B 基线 18.76 m²，B2 基线 14.44 m²）；
  - 每级踏步高 ≤ 0.18 m（基线 0.15 m）。

**路线 W：**

- 安装位必须是 `a2_install_option` 可行集里的一个点。重测时要满足：
  1. 檐口矩形在任何高度都不碰 A2 构件，LOD0 和 LOD1 都要测；
  2. r 0.45 从院门到两座屋门前（局部 (−3.0, −0.6)、(0.6, −3.8)）仍然连通；
  3. 棚下可达比例 ≥ 0.5（参考位基线 0.973）；
  4. 净高：系梁底离地 ≥ 2.10 m（基线 2.42 m）。
- 如果 010 要求棚下放储物件：只能用从 B GLB 切出的原箱和原台案（标「从 GLB 重建」）。放进去以后，同样按路线 R 的面可达规则再跑一遍。

**负例：**

- N2（已有）：檐口压进西屋，必须检出碰撞。
- N4（已有）：在箱子前面加一个 0.9 m 的阻挡，+x 面的可达距离必须从 0.35 升到大于 0.70（实测升到 1.25）。

## T3 未选候选完全不加载（验收第 2 条）

- 静态检查：在合并提案里的 city-data（overlay）上，grep 下列文件名。未被 010 选中的，出现次数必须是 0：
  - `workshed-LOD`、`workyard-LOD`
  - `m-courtyard-family/files/{baseline,north,south}`
  - `B-LOD0-C2`、`B2-LOD0-C2`
  - `compact_work`
- 基线：除 p-luoyang.asset.json 的 related 字段外，全部是 0 次。
- 运行时检查：按 city-renderer.mjs:221 的规则，模拟初始集合 `initial!==false`，并对 focusChapter 和 focusCourtyard 取并集。未选候选的节点 id 不能出现在任何集合里。
- 负例：把 workshed 节点设成 `initial:true` 但不在 010 的选用表里，检查必须失败。
- 撤回测试：装上再撤回以后，所选院的矩阵、原型 SHA 和节点集合要和安装前逐字节一致。B 院的原位棚不能被改动或隐藏。

## T4 不造成功能冲突（验收第 3 条，前半）

- 路线 W：
  - 棚檐口和 LY-044 灶台工作域、LY-045 圈厕、LY-048 服务口的已冻结占位要逐对做矩形相交，然后按 LY-006 的归属表判定。
  - 基线：409 个可行位里，有 65 个离灶台试放点 1.5 m 以上。
  - 负例：选一个和灶台相交的可行位，检查必须失败。
- 路线 R：现有布局不新增设施，只需确认没有别的席位的件落进棚的盒子（B：局部 x −7.2…−4.4、z −0.4…5.4）或储藏屋地台里。

## T5 不制造「新增建筑数量」假象（验收第 3 条，后半）

- 规则检查（`selftest_ly047.py` 的 `exclusivity_ok`）：一院最多一个棚或储藏候选。B/B2 已经算 1 个，再加 workshed 就必须失败（负例 N3 已检出）。
- 计数检查：合并后 provenance 的 courtyards 仍是 44；院型计数不变；buildings 或类似计数不能因为 workshed 加 1。workshed 只能作为「设施变体」登记在 LY-050 的清单里。
- 负例：如果 assembly 把 workshed 写成新 family，或者让院数变成 45，必须失败。

## T6 独立复核和自检

- `blender_crosscheck.py`（Blender 5.2.1 自带 glTF 导入器）必须复现以下数字：
  - 棚盒内 y=0.2 的顶点（拆分法线后 B 为 120 个、B2 为 114 个）；
  - 棚上方最低构件 y 2.35；
  - workshed 外包 [−4.05, 0, −4.45]…[4.05, 4.1297, 0.45]。
- `selftest_ly047.py`：P1、P2、P3 通过，N1–N4 全部检出，`allBehaved: true`。
- 局限，验收时要照写：
  - 这是 0.05 m 栅格、竖直射线和圆盘膨胀，不是实体碰撞穷尽，也不是连续人体或货物运动；
  - 没有做 GPU、浏览器或手机测试；
  - 不认证结构、承载、防火或防水；
  - 所有尺寸都是 C。
