# F01 · 验收范围

## 文件与几何
- Blender 原场景、GLB、三张实际相机渲染、生成脚本、检查脚本和本地 Three.js 依赖均保留。
- 独立展厅低模盒体、两件既有原创模型与新增文字共同导出。最终统计见 `geometry.json`。
- 检查：全导出三角面零面积、同网格重复坐标三角面；不是全部自交／共面重叠的完备证明。
- 新展厅的台座与底板接触、门框横梁与立柱接头为设计装配；原模型内部的已分类嵌入接触仍存在。不能声称全部穿插为零。
- 展品底部与展台顶面保留 0.25 单位的概念悬浮间隙；非制造装配。轨道阈值条接触步道顶面，不使用两个叠在一起的可见面。
- 六条相机目的地组合各采样 101 点，共 606 点；相机始终在展厅前侧，Z≥7.8、Y≥4.5。单纯相机位置净空不证明画面无遮挡。

## 交互
- URL parser、插值端点、越界夹取、所有目的地路径由 Node 测试。
- 源码审查：链接可键盘访问；不锁滚动；无驾驶要求；正文不依赖 JS；失败时保留实际渲染图与全部文本。
- 当前云浏览器 GL 禁用，不能验证 WebGL 材质、点击命中、实时相机、帧率或 z-fighting。不绕过安全配置。
- 实际浏览器集成复查结果见下；宽度模拟不是物理手机。减少动态只做源码／数学检查，真实 GPU 过渡仍未验。

## 使用
从 HTTP 静态服务器访问 `index.html`，不依赖在线 CDN。目录应置于总览 `fusions/F01/`，对应作品与设计复盘链接指向 `../../studies/001/`、`../../studies/002/`。直接打开孤立 HTML 文件的浏览器 `file:` 限制可能阻止模块／GLB加载，但全文仍可读。

最终几何统计：48 个网格，108,090 个三角面；零面积 0，同网格重复坐标三角面 0。新字形导出过程由 8 个零面积面改至 0（细小面积容差与 float32 导出复查共同判断）。

## 集成浏览器已确认的有限范围
总览复查实际观察：hall→orbit 同步 hash／图像；进入阅读列表仍保留 orbit；浏览器后退恢复 orbit；tide→后退恢复 orbit。首次 1188×761 视觉检查发现导航落在大图下方，已修复布局并提交重验。修订后桌面截图确认完整相机图与目的地导航同时可见。


最终 scoped 浏览器复查：
- 320／390／768 iframe 的实际内容宽度分别 305／375／753 CSS px，均等于 scrollWidth，无水平溢出；三章图像自然宽度 1440，资源加载成功。
- 320 宽度下用键盘 Enter 选择潮翼，图像变为 `assets/tide.png`，对应导航 `aria-current=location`。
- 无 JS 使用 sandbox allow-same-origin、不含 allow-scripts：真实序厅图正常，潮翼锚点可以到达可阅读的潮翼正文；不存在卡住的加载层。无 JS 不切图是完整阅读列表的预期模式。
- 原始 1188×761 首屏导航不可见问题，已在导航前置／标题压紧后以实际截图复核。
- 未验：物理手机、200% 缩放、完整读屏语音、GPU 动态与热点、帧率、实时 z-fighting。

导出几何另做保守 AABB 广相位：原模型与新展厅环境的正体积重叠候选 0；新环境内部有 4 对横梁／立柱接头，均属有意装配。原模型内部装配对不在本项检查范围，不能扩张成“全场景全部穿模清零”。
