# 可探索 3D 网页的组成与评审方法

检索日期：2026-11-02。

版本说明：此为依据保留正文恢复的早期清单版，用于展示方法演进；并非旧文件的字节级恢复。SD01 评价对应当时 v0.2，不作为后续版本现状。

本文讨论以整页三维空间为主体验的网页，不是普通文章里的模型查看器。它是本项目的设计与评审框架，**不是行业强制标准**。判断重点是：用户能否进入空间、辨认目标、进行有意义的观察或操作、得到内容、恢复或退出，而不是模型与特效数量。

## 功能必需与实现选配

- **必需功能**：目标清楚、内容可达、空间关系可理解、视角可控、操作有反馈、可以返回或恢复，以及可接受的加载、失败处理和替代访问路径。
- **依目标选配**：自由行走、车辆、物理碰撞、地图、传送、配置器、任务、空间声音、昼夜系统等。每项应说明服务什么内容或任务。
- **装饰候选**：删掉后不影响定位、理解、操作或任务完成的景物与效果。装饰不是禁用项，但应排在主体验之后，并承担性能成本。

装饰是作用，不是技术类别。雾可以帮助远近辨识，声音可以提供方向或操作反馈，动画可以解释状态变化。建筑、天空、地面不必全部存在；纯抽象空间同样可以成立。必需的是可理解的组织，不是现实世界物件清单。

## 十维组成清单

| 维度 | 必需功能 | 依目标选配与取舍 |
| --- | --- | --- |
| 1 目标与核心内容 | 明确为谁设计、来做什么、最后应理解或完成什么 | 作品浏览、机制学习、产品配置、创作、品牌体验；不要混成无优先级的功能集合 |
| 2 空间布局 | 入口、目的地、区域关系、边界与尺度有可读线索 | 房间、岛屿、街区、分层空间、传送门；空间路径应有内容理由 |
| 3 主体与环境 | 主体清楚，环境提供必要参照，不压过内容 | 建筑、植被、水、人物、车辆、抽象几何；无任务作用的摆件属于装饰候选 |
| 4 材质与光 | 可见性、主次、深度线索与风格一致 | 实时或烘焙光、阴影、PBR、反射、雾、后期；不必追求全部写实 |
| 5 镜头与移动 | 初始视角合理、可控制且不易迷失，可回到有效观察位置 | 俯视、第一或第三人称、轨道观察、导览；镜头应支持具体观察任务，不只是展示空间 |
| 6 交互与反馈 | 可操作对象可辨识，动作有结果，可恢复、撤销或返回 | 拾取、拖放、拆解、搭建、配置、物理、任务；先设计操作带来的理解，再选择技术 |
| 7 导航与界面 | 操作提示、目标入口、方向线索、返回与恢复始终可用 | 地图、指南针、搜索、快捷传送、进度；地图不是每站必需，辨方向才是必需 |
| 8 内容与叙事 | 信息层级明确，关键内容不只藏在难发现的角落 | 热点说明、章节、任务线、讲解角色、时间线；允许跳过开场，避免强迫等待 |
| 9 动画声音与模拟 | 必要状态变化可理解；使用声音时可关闭，静音不丢关键内容 | 转场、环境动画、旁白、空间音频、物理、天气；持续粒子和无目的摇镜应谨慎 |
| 10 加载性能适配与无障碍 | 可理解的加载和失败状态，设备预算，键盘与触屏路径，可读文字与替代内容 | 压缩、实例化、分区加载、LOD、自适应画质、2D 模式；减少运动、焦点管理和屏幕阅读器需真实验证 |

十维不是十个独立模块。目标决定空间布局，任务决定镜头与交互，内容决定导航；性能和可达性贯穿全过程。

## 三个原作者案例

### Bruno Simon 让作品集成为驾驶空间

作者官网明确邀请访客驾驶探索，列出键鼠、触屏、手柄输入，以及地图、重生、静音、画质开关。作者仓库 README 描述输入、物理、玩家、视图、区域与交互点、渲染的更新顺序，并列出 GPU 友好纹理与 UI 图片的压缩流程。[官网](https://bruno-simon.com/?lang=en) · [作者仓库](https://github.com/brunosimon/folio-2025)

**设计推论**：驾驶建立辨识度，也增加学习与迷路成本，因此导航、操作提示和脱困不是附属美化。车辆、物理、天气和昼夜是此项目的体验选择，不是所有 3D 网页的基础要求。

### Choo Choo World 围绕搭建运行与分享组织空间

Lusion 将其定义为面向不同年龄用户的创作小游戏，并说明分享快照的参与机制。实站可读教程列有镜头平移、旋转与缩放、45° 快捷旋转、编辑与观看模式、撤销与重建、列车播放控制；界面文字还包含声音设置、导出图片及不支持设备、浏览器或 WebGL 的提示。[作者项目说明](https://lusion.co/projects/choo_choo_world/) · [项目实站](https://choochooworld.com/)

**设计推论**：核心是“搭建—运行—观看—分享”，不是无目的漫游。错误恢复和模式切换直接服务创作，比增加景物重要。分享适合能产出用户成果的体验，不应机械移植。

### Of The Oak 用视觉空间连接科普内容

Lusion 说明该网站是实体装置的网页延伸，为线上和现场观众提供深入理解项目的入口。其管线将复杂树、枝与节点结构压缩为约 3.5 MB 的自定义格式，并采用 WebGL instancing；这一数字不是整个网站的总下载体积。实站可读内容包括跳过开场、冥想体验和物种探索入口。[作者项目说明](https://lusion.co/projects/of_the_oak/) · [项目实站](https://oftheoak.co.uk/)

**设计推论**：视觉复杂度不应直接等于重模型下载；资产管线与内容分支需要一并设计。跳过机制和清楚的内容入口，可以让空间体验不阻塞信息访问。

## 证据类型与使用限度

本次案例证据来自上述原作者网页正文、实站可读界面文案和作者仓库 README。正文能支持作者目标与技术说明，界面文案能支持所声明的入口与控制设计，README 能支持公开的系统组织和资产处理流程。

这些证据**不等于实际 GPU 渲染与操作验收**：本次未据此确认帧率、触屏手感、实时光材质表现、设备兼容性或真实降级效果。页面中存在错误提示文案，也不代表失败路径已经实测通过。设计推论已与来源事实分开。奖项、热度与技术新旧不作为可用性证明。

## 对 SD01 的应用

依据现有代码评审，SD01 已以全视口场景作为主入口，但主要仍是可绕看的两件模型展台：用户能移动视角和打开说明，尚缺“看到什么—做什么—发生什么—理解什么”的操作学习链。这是设计与代码层面的判断，不是 GPU 体验测试结论。

下一步应先明确一个学习任务，例如通过观察方向和受限操作理解转动连接或插接方向；让全景负责定位、局部视角负责看接点、返回空间负责比较。先完成一处可验证的小体验，再扩展另一处。新增建筑、小地图、热区和进度条可以改善导航，却不能单独解决内容与空间脱节的问题。

## 可复用评审问题

1. 不读长说明，用户能否知道来做什么、第一步做什么？
2. 每个区域为什么存在？它与其他区域的关系是否可辨？
3. 三维观察或操作带来了二维卡片难以表达的什么信息？
4. 是否能写出一条完整的“看到—操作—反馈—理解”链？
5. 可操作对象与装饰是否容易区分？错误操作能否恢复？
6. 镜头是否揭示内容，而不只是把模型框进画面？
7. 迷路、卡住、关闭弹层后，能否继续或回到起点？
8. 关键内容能否不用精细鼠标操作、强制运动或声音来获取？
9. 在低性能设备、资源失败和无 3D 支持时，用户还剩什么可用功能？
10. 删除某项效果会损失哪项功能？若没有，它的视觉收益是否值得性能成本？
11. 结论分别由文案、代码、静态图、实时 GPU、真机或用户测试中的哪一级证据支持？

最小完整版本可以只有一个主题空间、少量明确目的地、一种可靠移动方式、内容交互、方向与恢复机制，加上加载失败处理和替代内容。先证明探索与理解闭环，再增加模拟和装饰。
