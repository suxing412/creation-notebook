造物手记工作法 v2 · 2026.11.01

把一次修好，
变成下次可复现。

不是收集更多“通过”，而是写清在什么条件下，什么证据足以支持什么结论。从真实失败里提炼规则，换一个模型时仍知道哪些可以继承、哪些必须重做。

执行检查清单 ↗下载契约模板 ↓源 JSON ↓

16 条准则 · 6 类契约 · 零图片／模型复制 · 纯静态阅读
方法整理，不新增常规作品、融合轮或几何配方。

先说边界

本轮只读审阅既有证据，没有重新跑旧模型、浏览器、GPU 或渲染测试，也没有新增联网研究。有限样本和反例回归不是全域证明；本页不是通用模型检查器。

路线

从这次要做的事开始

生成新参数组合先锁家族与不变量，再验真实网格。把原件放进新场景分清文件同一、几何保真与投影一致。让作品成为网页阅读不中断，异步不串扰，发布不夹带。

值得继承的不是“始终正确”

旧错误 PASS，
也是资产的一部分。

  1. 005 · 合法接触旁的异常同一 pair 仍能藏穿出体与包容岛；靠名字放行不够。
  2. 006 · 精度与坐标系double 后处理救不回 float32 量化；局部正体积不保证世界朝外。
  3. F03 · 独立生命周期3D 失败不该取消用户正在打开的章节。

新反例揭示检查器盲区，不等于原始交付件已损坏。005 未追改为 006 门禁。坏二进制与原始日志不在本包内。

01

参数

回目录 ↑
P01

输入可接受，不等于几何已安全

把输入域、已生成网格、已验收效果分成三张清单。

真实案例　陶瓷翼 swept 的参数均在范围内，初版仍有 4 对尾缘铜管非相邻自交；全族铜边半径从 .023 统一减至 .016 后，三个预设复查通过。006 的 512 个参数盒角点只跑 validator：320 接受、192 拒绝；没有生成 320 个网格。

怎么用 · 适用边界与成本
采用
先锁定造型家族、构造不变量与耦合约束；每个新参数组合重新验几何与多视角。记录被拒组合及修改原因，改全族规则后重跑已有预设。
不采用
不把滑块上下限写成安全域证明；不给坏样本隐藏例外，不删除失败检测，不把有限反例回归称为全域证明。
适用
固定构造、固定拓扑或明确变拓扑规则的受限参数化家族。
不适用
任意导入网格、任意曲面、未验证的新家族；已接受的角点也不能自动推到内部连续域。
成本取舍
输入测试便宜；真实网格生成和检查随样本数增长。先检耦合约束再投渲染预算；记录实际样本数而非暗示遍历。

P02

同样效果，要锁定的不只是 seed

把版本、构造、归一化、材料、光照、色彩管理和相机一起保存。

真实案例　陶瓷翼仅接受 Blender 4.3.2 和 seed 0；三个预设换轮廓而不换摄影。相同环境两次 baseline 的 GLB 字节一致。006 固定材料和摄影后，Atlas 仍因表面朝向更亮，不能把同条件误写成同亮度。

怎么用 · 适用边界与成本
采用
写清物理或抽象单位、开放参数、锁定参数、生成器版本、网格分辨率、色彩约定与摄影条件；同环境复现用字节哈希，视觉语言另做人工多视角。
不采用
不承诺跨硬件逐像素一致；不为掩盖几何比例而临时换材质、机位或曝光；不把线性 RGB 当 CSS sRGB。
适用
目标是复现同一视觉语言的受约束资产族，且可保存实际摄影场景。
不适用
跨渲染器光照等价、GPU 色彩一致、制造材料一致，以及未记录环境的复现。
成本取舍
保存配置和场景成本低；跨环境回归另计。审美检查不能由一个未经定义的分数替代。

02

几何

回目录 ↑
G01

合法接触，不能豁免同一构件对的其它几何

禁止只写 allowedPairs；每对接触必须有有限区域、端点／嵌深和整体包络。

真实案例　005 的 pin–diffuser 保留原接触后，加一个 1.4×1.4×12 mm 棱柱仍被旧门禁错误 PASS；在 hub 对象中另加一个完全位于罩体内、远离实际套筒的 0.4 mm 岛也错误 PASS。最终加入单连通、有限销／套筒全顶点包络与接点 Z 窗口后被专用字段拒绝。

怎么用 · 适用边界与成本
采用
先列完整构件对矩阵；分离对拒绝相交与包容，装配对写坐标系、范围、深度、连通数、整体形状约束。用“原合法接触仍在＋旁边新增异常”做反例。
不采用
不因 pair 名称允许就整对放行；不把 BVH 零交线当无包容；不拿单连通独自当无自交证明。
适用
能定义销、套筒、嵌件等有限装配语义的家族。005 是 8 件、28 对、9 对指定装配。
不适用
006 单壳没有装配 pair；灯的半径和 Z 包络不能直接用于折板。制造装配、锁定、防脱和热设计也不由此证明。
成本取舍
需要作者先定义几何语义，比名字白名单贵；但能让失败指向具体接点或包络，不必每次人工猜测。

G02

局部绕序与世界朝向，各验一次

闭合、总正体积和局部绕序不能互相替代；所有判定先声明坐标系。

真实案例　005 反转底座单面，旧总有向体积仍正，曾错误 PASS；最终由 3 条绕序不一致边拒绝。006 用局部 X 镜像＋对象 X 缩放 −1＋全反面保持世界位置，却让局部体积约 +0.000340456822 m³、世界体积约 −0.000340456822 m³；旧门禁真实错误 PASS。

怎么用 · 适用边界与成本
采用
检查二面边的局部一致绕序，再以世界三角计算有向体积。006 另要求 identity 世界矩阵，并用专用世界负体积字段验证反例，而非只靠变换例外拒绝。
不采用
不以“闭合＋正局部体积”称世界面朝外；不把新反例表述成原交付件已坏。005 冻结源码未被追改，也不声称它已具有 006 的世界体积修复。
适用
要求闭合、定向、有限世界变换的静态实体模型。
不适用
开放薄片不适用正实体体积门槛；合法负缩放场景应定义相应朝向规则，而非盲目移植 identity 限制。
成本取舍
绕序与世界体积计算通常比渲染便宜；代价在于正确处理坐标系与声明允许状态。

G03

double 不能恢复已经丢掉的 float32 精度

容差要绑定尺度、存储精度和正反控制组；称近共面，不称精确证明。

真实案例　005 的 float32 单位法向量自点积曾低于 1−1e−8；改双精度后，006 的约 0.227 mm 短边／248.7 mm 长边窄三角仍发生量化：法向 dot≈0.9999999955，双向平面残差约 8.823／12.039 nm。旧专项漏报，但整体因别项拒绝。

怎么用 · 适用边界与成本
采用
006 在本尺度用 cos≥1−1e−7、双向点平面距离≤50 nm、二维 SAT 每轴正重叠阈值 10 nm。原内缩反例专项 0→1；沿法向移开 1 µm 控制组专项为 0。记录角阈值、距离和单位，不混成“面积阈值 10 nm”。
不采用
不直接复制这些数值到其它尺度；不把整体拒绝当共面专项覆盖；不把近共面阈值当 GPU z-fighting 阈值。
适用
已知单位、三角尺度和顶点存储精度的数值网格检查，配套真实窄斜面反例。
不适用
符号几何精确共面、连续曲面相交证明、GPU 深度缓冲行为。BVH 排除共享顶点的限制仍在。
成本取舍
双向平面与候选过滤增加少量计算；阈值回归需要保留旧失败和移离控制，不能只不断放宽到“通过”。

G04

检查 raw mesh，就明确拒绝未支持的显示状态

纯模型与摄影场景使用不同契约；没有评估的状态不得默许。

真实案例　006 的 Solidify 与 Shape Key 反例添加前后 raw 顶点／面 SHA 完全相同，其它几何缺陷字段为空；最终仍分别由 modifiers_present 与 shape_keys_present 拒绝。纯模型恰好一件壳体，摄影场景则包含地面、相机和灯。

怎么用 · 适用边界与成本
采用
作者声明检查 raw 还是 evaluated geometry；若仅 raw，列出并拒绝 modifier、shape key、constraint、parent、animation／driver 等未支持状态。按家族约束全部顶点和索引关系。
不采用
不把 ob.data 没变等同于实际显示没变；不把 006 的顶点恒等约束当任意网格检查器，它会拒绝合法重索引。
适用
约束明确、可控制生成过程的纯静态模型。
不适用
任意 Blender 动画或修改器栈；需要 evaluated scene 的项目必须另建检查流程，不得在模板中悄悄放开。
成本取舍
状态枚举便宜；全面 evaluated 几何审查更贵。选择不支持某类状态时，拒绝比假装兼容可靠。

03

文件身份

回目录 ↑
I01

GLB 声明看起来正确，实际字节仍可能坏

从 buffer 解码坐标、法线和索引，不能只读 accessor min／max。

真实案例　005 把 POSITION 中一个坐标改成 NaN，或者把实际索引改成 65535，而声明保持不变，旧门禁均错误 PASS。修复后分别由 Nonfinite accessor bytes 和 Index exceeds POSITION count 拒绝。006 增补零法线、过小 stride、越界 bufferView 和负 offset 的实际故障。

怎么用 · 适用边界与成本
采用
对受支持格式验证 offset／stride／对齐／边界，再解码数值、索引范围、法线长度与三角面积；逐项对照声明极值。保留 loader 解析与 payload 检查为两项证据。
不采用
不拿能加载或 min／max 合理替代真实字节检查；不称 payload 验收为 GPU 渲染、全拓扑等价或所有 glTF 扩展兼容。
适用
明确支持的 GLB 版本、primitive 与 accessor 形态。
不适用
未实现的压缩／稀疏／外部资源扩展、GPU 材质效果和原生模型全同构证明。
成本取舍
线性解码增加读字节成本，通常比出图便宜；先拒绝坏 payload 可避免将资源浪费在渲染或分发。

I02

字节同一，与几何保真是两个命题

原件用 SHA-256 冻结；重保存／重导出后按实际变化选择证据。

真实案例　005 正式 native／GLB 均与已审资产哈希一致。006 正式 native 重新保存，不与候选字节相同，故按最终 native 自身 SHA 重跑；三个 GLB 与候选相同。F03 的 Folio 重导出从 6072 拆为 6098 顶点，双向最近世界顶点最大误差约 3.332e−8 m。

怎么用 · 适用边界与成本
采用
报告绑定模型、配置、生成器与 checker 身份。组合场景分别记录源／导出数量、世界变换、双向距离和 PBR payload；F03 使用 5e−6 m 几何距离容差。
不采用
不强迫重导出顶点数相等；不把点集距离当拓扑索引同一；不借候选的旧通过证明最终已重新保存的文件。
适用
冻结原件的复用、受控重保存，以及明确世界变换的组合场景。
不适用
单靠点云距离不能保证所有面连接、纹理、动画或外观等价；检查目标改变时需增补指标。
成本取舍
哈希成本低；双向几何比对更贵且需容差。代价应由“究竟要保持什么”决定。

I03

退出成功，不等于这次检查真的成功

要求新报告、显式通过和输入身份；不接受陈旧结果代领成功。

真实案例　F03 曾把重导出的顶点拆分当损坏；其检查流程随后明确添加 Blender --python-exit-code 1，并要求生成新报告和 passed。源验证入口先删除预期旧报告，再要求本轮成功标记，防止默认 exit 0 或遗留文件混淆。 该入口见既有源码包内的 desk-atlas-F03/source/verify.py；本轮仅阅读，未执行。

怎么用 · 适用边界与成本
采用
运行前使用独立本轮报告名或清除目标旧报告；记录实际命令、退出码、checker／输入 SHA；执行失败、报告缺失、身份不符或 passed 非 true，均不得进入该层已通过。
不采用
不只看进程 exit 0；不把旧报告改日期复用；不靠日志里某个 PASS 字样替代结构化报告的身份和结果。
适用
会由包装器运行 Blender／导出器／离线检查程序的构建流程。
不适用
报告新鲜本身不说明算法正确；专用反例覆盖和人工评审仍独立存在。
成本取舍
少量包装逻辑即可避免昂贵误交付；本页不提供可放行任意模型的脚本，只提供作者必须填的契约。

04

浏览器状态

回目录 ↑
B01

图片路由与 3D 会话，分开取消

只允许最新路由在图片 decode 成功后提交；3D 的取消不能取消阅读。

真实案例　F03 旧状态回归中，在 light 图片待解码时 3D 初始化失败，实际仍留 overview 而 hash 已是 #light。修复后 routeEpoch 与 liveEpoch 分离，挂起章节正常提交；取消旧 parse 后重启，旧资源完成只释放自己，不接管或销毁新会话。

怎么用 · 适用边界与成本
采用
路由加载拥有自己的序列号；图片、标题、热点一起提交。3D 初始化用独立 token／AbortController；提供取消、重试、主动回离线。回退与前进恢复该历史项记录的场景。
不采用
不在坏图时给旧图贴新标签；不让 renderer 错误清空路由；不以 stub renderer 的通过声称真实 GPU 生命周期已验。
适用
异步加载图片、模块、配置与可选 3D 的内容站。
不适用
Node VM 只验证状态逻辑；真实浏览器历史、焦点与 GPU 资源回收需分别验证。
成本取舍
增加显式状态与乱序用例，但比事后处理偶发错图更可控。测取消／重启／回退，不只测 happy path。

B02

先验主任务看得见，再验没有溢出

首屏门禁要包含场景、原生目录与关键动作；点击目标与可见圆片分开设计。

真实案例　F03 首版桌面约从 y455 才开始，主要区域被截。修订后在 1188×761 视口，场景 y257–694、目录 y168–237、3D 按钮 y648–682 同屏。窄屏即使 44×44 目标不重叠，大圆片仍遮灯罩，遂保留透明目标、可见片减为 19×19 并去光晕。

怎么用 · 适用边界与成本
采用
用真实首屏截图／DOM 量测评估主任务；窄屏检查目标分离，也人工看遮挡。给编号保留完整可访问名称与正文无标注图。
不采用
不以 overflow hidden、锁页面高度或只测 scrollWidth 粉饰通过；不把小 iframe 叫真实手机验收。
适用
以场景或图像为主任务、同时必须能导航与阅读的响应式页面。
不适用
这一组尺寸不是所有页面的规范；44×44 也不自动证明触屏、键盘或读屏器体验。
成本取舍
需要至少桌面和窄屏实看；几何对齐与无溢出是低成本筛查，不能代替可读性判断。
