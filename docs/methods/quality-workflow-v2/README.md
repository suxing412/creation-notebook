# 造物手记工作法 v2

把一次真实修复，整理成下一次可以执行、能够追问边界的方法。它是造物手记的**方法资产**，不计常规 007、融合 F04，也不是第二个几何配方。

## 交付内容

- `index.html`：完整静态方法页。无 JavaScript、无外部字体、无图片、无模型依赖；正文不需要联网。
- `methods.json`：16 条条件化准则，按参数、几何、文件身份、浏览器状态、相机投影、发布体积分组；每条含案例、采用／不采用、适用／不适用、定性成本与公开证据。
- `checklist.md`：有停止条件的执行清单；不是自动模型放行器。
- `contract-template.json`：待作者按几何家族填的契约，初始为“未填写，不可放行”。不含可直接放行的 `allowedPairs` 白名单。
- `evidence-index.json`：本轮实际读取的既有公开证据路径、字节数和 SHA-256。只引用，不复制旧图片、模型或原始日志。
- `source/build.py`：由 JSON 生成静态页面、索引与清单。只用 Python 标准库，不执行模型检查或启动服务。
- `source/verify.py`：校验本方法包结构、内部／证据链接、文件身份与体积边界。通过只代表本方法包检查通过，不代表任意几何或 GPU 通过。
- `verification.json`：本轮实际方法包检查结果，严格注明检查范围和未验。
- `manifest.json`：交付文件清单、SHA-256 与字节数；清单不哈希自己。

## 怎样使用

1. 先读参数与几何准则，确认自己的资产属于哪个可约束家族。
2. 复制契约模板，填单位、坐标系、拓扑、参数耦合、状态、构件对和专项反例；所有空项须解决或以理由标不适用。
3. 按检查清单执行现有家族工具，并绑定最终文件与检查器 SHA。缺少本家族实现时，模板不能授予通过。
4. 把新失败连同旧结论、修复、专项结果和限制作为下一版方法证据，而不是给新样本添加隐蔽豁免。

**必须拒绝的契约**：只说“这两个 object 可以接触”，却不限制接点范围、端点嵌深、完整构件形状或额外包容岛；只对缺陷整体拒绝，不验证所声称的专项字段。这里没有复制 005／006 检查器作黑箱通用工具。

## 构建与只读校验

在本目录执行，将 `--evidence-root` 指向已有图库的发布根目录：

```sh
python source/build.py --evidence-root 已有图库发布根目录
python source/verify.py --evidence-root 已有图库发布根目录
```

构建仅写本方法目录；校验只读取已有图库。命令不重新跑模型、Blender、GPU 或浏览器。最终清单在校验结果写入后生成；重复执行同一命令不改变旧作品。

## 部署契约

复制本目录到图库 `methods/quality-workflow-v2/`。入口是 `methods/quality-workflow-v2/index.html`，返回链接为 `../../index.html`，证据指向 `../../studies/005/…`、`../../studies/006/…`、`../../fusions/F03/…` 与 `../../recipes/ceramic-wing-v1/…`。

单独下载可阅读全部正文，但这些旧证据和返回链接需要图库布局；不将它们打包重复下载。本包所有文件合计预算 **<1,000,000 字节**，不是整个图库预算。源文件直接交付，避免再嵌一份重复 ZIP。

## 仍未建立的保证

- 有限反例与离散组合不是完整连续参数域或任意模型的证明。
- 已有几何门禁的 BVH 共享顶点排除、数值容差和采样限制仍存在。
- GPU 材质／动态闪烁／真实 WebGL 对象点击、真实 iPhone／触控及制造／物理性能不在已有通过结论内。
- 本方法页的静态构建与链接检查不是原生浏览器布局验收；浏览器状态以 `verification.json` 为准。不能拿 F03 的浏览器验收替本页担保。

## 更新原则

先新增可复查证据，再修改方法版本；保留失败历史和证据身份。新结果若只缩小某个已知缺口，就只说缩小了这个缺口，不宣布“彻底解决”。新增方法入口不改变作品或配方计数。
