已实际复查

- 实际模型接入后的桌面首页：整灯轮廓可在首屏辨认，文字/主图并置；主图不裁切。

- 受控 iframe 的 320、390、768、1280、1600、1920 CSS 视口：内容 scrollWidth 均不超过 clientWidth。实际内容宽依次为 305、375、753、1265、1585、1905 CSS px（浏览器滚动条占 15 px）。这是真实浏览器中的 CSS 视口，不是手机硬件。

- 320 视口下直接跳至参数矩阵并查看：中文参数、英文键名和三个数值列同时可读，没有要求横向滚动。

- 1600 / 1920 视口的 hero 元素测得 585×650，原图 900×1000，object-fit:contain；纵横比匹配，避免先前超宽屏不确定高度造成的截底风险。没有据此宣称物理大屏或 GPU 测试。

- 键盘在主页面执行 Hush → Tab/Enter 至 Poise → Tab/Space 至 Reach：选中、名称、尺寸、alt、原图和 GLB 链接同步。焦点仍留在按钮，无焦点陷阱。

- 390 视口无 JavaScript iframe：三变体、参数矩阵和 10 个下载入口保留；交互增强控件不伪装可用；原生 details 用 Enter 展开，参数边界可读。

- 页面复制命令按钮返回成功反馈；剪贴板不可用路径另有假 DOM 单元测试，不把该单元测试算真实权限拒绝测试。

- 独立 /qa/failure/ 副本仅使 Reach 切换图真实 404，JS/CSS 使用正式同文件：Hush 成功 → Reach 失败后保留 Hush 图、名称、尺寸与选中态，状态明确说明失败；随后 Poise 恢复成功。

- 独立 /qa/initial-failure/ 副本使首页 Poise 图片真实 404：页面明确没有成功加载的首页图，再选 Poise 仍准确提示；选择 Reach 后恢复图片、信息和下载，移除失败提示。

- 390×360 CSS 视口中，无脚本复现命令可折行阅读，原生展开项和资料链接仍可滚动到达；没有固定遮罩或焦点锁。
