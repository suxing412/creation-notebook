# 006 · 网页复盘

## 目标不是“更像工程图”

首版只用蓝白与细线，技术感仍主要靠文案。改进必须来自真实信息结构：完整路径说明四次转向，局部图显示厚度与半径的关系，三变体使用同一比例尺。无法给出处的线和数字不画。

## 已带来的变化

- 首屏压缩头部留白，让整物先被看清。不是更大字标或更多动画。
- 名义输入、解析派生、离散网格检查在颜色和栏目位置上分开；读者能判断每个数字由哪一步得来。
- 图版加载先验证，再共同提交图像、替代文本、图注与原图入口。失败保留最后成功状态，首图尚无成功则诚实显示无图。
- 独立审查发现了真实的“初始图片晚到”竞态：即使已经开始另一请求，原始HTML图片仍可能成功。不能只测试从已加载首图出发的快乐路径。

## 仍需要克制

图解与统计不是材料和制造保证。中心截面采样与有限离散测量不证明任意位置最小厚度；端部平面圆角也不等于端盖全方向倒圆。CPU图版不等于浏览器GPU；模拟CSS视口不等于手机。

## 下一轮带走的两点

1. 先写每张图回答的问题、数据来源与坐标变换，再排版；图解本身也必须可复现。
2. 把首图未完成的时间窗纳入状态设计；“最后成功”是一项需要追踪的事实，不是默认存在的概念。

## 本轮收口

最终模型包已原样接入，实际主页面的六档CSS宽度、无JS短屏、键盘切图与参数展开、真实404保留和恢复均留下限定证据。独立观察器的禁GL保底与三变体切换完成；这仍不等于GPU或制造验收。冻结输入与观察器候选逐字节相同，不能因为包名变成final就省略身份核对。

交付复核还揭示了视觉工作之外的三项问题：黑名单会漏临时文件，单纯哈希可以封住失败目录，半途解压可能破坏旧输入。修订为明确允许集合、先跑门禁再写哈希、完整暂存校验与失败回滚。原先反例在独立隔离复测中被拒。数字资产的质量还包括这些看不见的失败路径。

下一轮优先延续可复现图解与证据层级，不机械复制本页蓝白配色。真实GPU、真机、读屏与制造性能仍须在具备对应条件时独立验证。
