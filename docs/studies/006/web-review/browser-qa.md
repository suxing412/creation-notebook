## 草稿阶段已实际观察

- 首版1173×751有明确占位。缩短页头和首图上距之后，真实草稿整体轮廓在首屏可辨。
- 路径章节最初B2标注越过图版边缘，压到图例；实际看见后改引线与标注避让。根线程另tab复看，B1–B4与右列讲解对应清楚。
- 受控iframe的320、390、768、1280、1600、1920 CSS视口：clientWidth分别305、375、753、1265、1585、1905，无横向溢出。15px差值为浏览器滚动条。此记录对应真实草稿阶段，最终资产仍须复检。
- 320视口路径章节原1.9倍SVG标签偏小，调整为2.7倍后已在原生浏览器复看：B1–B4可辨，没有压住图例；几何线条仍使用同一坐标。

## 独立静态审查与假DOM测试

- 首图尚未结束时切换另一图版：旧实现忽略首图晚到的成功事件，后续404会误说没有成功图。改为区分初始HTML图事件与增强提交，允许跟踪首图实际加载，不覆盖较新请求的状态。
- 11项假DOM测试覆盖成功同步、保留最后成功、首图404、恢复、重试、较新成功优先、旧失败不能反覆盖、首图晚到成功后另一图404等。假DOM不是浏览器、读屏或GPU验收。
- 厚度章节的浅色焦点已存在；独立审查发现通用hover蓝覆盖深蓝背景时对比低，现单独改浅蓝hover。指定色对计算另列。

### 真实404，不是假成功

QA副本仅局部替换图片路径，使用同一正式app.js和style.css，结束后不进入交付。

- 选择坏接地图：实际404后保留beauty.png/960px、对应alt、图注、原图链接和“整体视角”选中态，提示加载失败；再点重试仍诚实保留成功图。
- 用Enter选择有效顶弯图：实际恢复到bend-detail.png/960px，alt、图注、原图和选中态共同更新，重试入口消失。
- 首图本身404：naturalWidth=0，明确提示无可加载主图，不虚构上一张成功图。用Space选择有效顶弯图后恢复，路径与参数始终保留。
