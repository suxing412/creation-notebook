# FOLIO 006 · 不足 → 改进 → 复检

## 1. 首版不是最终品

首版先以48采样上限、560²、CPU无降噪出三张图；根任务实际查看主图、侧面和弯折近景后，认为“连续厚壳明确，但普通折板架”。这与模型作者自评一致：等宽后片过满，前唇两端像直接裁切。没有为了辨识度随便加孔、logo或附着零件。

改为沿弧长平滑变宽：主体在中段最宽、顶部/后片收窄，后足约72–76%名义主体宽；前后端增加4mm**平面轮廓**真圆角。截面0.65mm微圆角原本就有，不能把smooth shading说成新增几何。`before-after.png` 前/后均为48上限/560²/同机位/同材质；其中顶图清楚显示实际宽度曲线，不用主图高光代替轮廓证据。

三款高采样对照的根评确认轮廓差异与家族语言成立。Atlas斜面更亮来自朝向/光照响应，不是换材质；固定摄影与材料并不保证每种几何相同明暗，场景审计会核对真实参数。

这仍是克制的折板架，不是假称已经找到史无前例的品类。新作的主要可复用价值是：少件、四弯、封闭厚壳、有限参数域、同规则三种折角与宽高比例。

## 2. 原作者检索如何改变决定

生成首版后，实际读取Johan van Hengel原作者项目页、Muuto Folded官方材料页和MOEBE Book Stand官方描述。`reference-notes.md` 分开记录已读文字、自己的推断、采用与不采用。只吸收“由片材和负空间解释用途”的方法；不下载原图/CAD，不复制壁挂口袋、品牌比例或联名语言。官方说某产品能制作/使用，不等于FOLIO被验证。

## 3. 前唇亮点不是凭印象解释

根任务在48采样前托近图看见右上角的小台阶/尖亮点，要求核实。实际560²相机射线命中表明：像素[290,332]来自端部4mm圆角第4站；邻域还同时看到后方托面转弯。`terminal-cap-diagnostic.png` 保持几何，改为漫反射体和橙色端盖后，该集中银白亮点消失，圆角轮廓保留。高采样 `assets/folio/contact-detail.png` 的局部也收敛为连续转角高光。

不能夸大：端盖厚度方向边仍是硬边，当前不是全方向倒圆。射线与诊断支持“局部曲率/法线的镜面高光”解释，不证明动态深度闪烁。不是用“全局QA通过”替代这项局部调查。第一次射线ROI选在后方托面而非亮点，已据实际放大图纠正；错ROI工作记录未当成最终证据。

## 4. 继承005，但不照搬灯的契约

006是一件壳体，没有销、灯罩、套筒，没有允许相交pair。继承的是有限坐标、连通分量、局部绕序、真实GLB字节解码、全顶点约束与共面双精度运算。灯的pin/hub半径包络不适用；替换为本配方所有世界顶点与索引循环的有限恒等约束。它会拒绝合法重索引，也不是通用几何证明。

同object新增穿出棱柱与完全包容小岛都真实测试，分别要求自交字段/连通字段命中。反转单面要局部绕序字段命中，坏GLB NaN和越界索引要实际字节检测命中；不靠其它失败项代领覆盖。

## 5. 本轮又实测出两项门禁缺口

### 窄斜三角的量化误差

即使改用双精度计算，原顶点仍是float32。短边仅约0.227mm、长边约248.7mm的三角内缩叠片，保存后法向dot约0.9999999955，双向平面残差约8.823/12.039nm。继承005的1−1e−10角阈值与10nm平面阈值使专项漏报，整体虽被其它项拒绝，但不能记为共面检测有效。

最终采用明确的“近共面”数值门禁：双向≤50nm、cos≥1−1e−7、SAT正面积>10nm；实际原反例命中，法向移开1µm控制组不命中。`test_coplanar_quantization.py` 从源码重建固定原triangle298，保留旧专项0→新专项1，不依赖公开坏二进制。阈值不是精确符号几何，更不等于GPU z-fighting深度阈值。

### 世界坐标与局部体积不一致

模型作者审读检查器后发现：世界坐标用于包络/BVH，但有向体积原来由局部mesh计算。真实构造“局部X镜像＋对象负X缩放抵消位置＋全反面”后，旧native错误PASS；原本正确的世界顶点并不保证表面朝外。旧报告 `gate-world-inversion-before.json` 留档。**这是新反例揭示的检查器盲区，不是原始Folio交付候选已内外反转。** 对未经注入的原始候选与正式资产需另行按新检查器验证。只读审阅005源码也发现相同局部体积逻辑；没有改动已冻结005，也没有据此宣称005原模型有缺陷，后续方法库应补充坐标系审计规则。

修复同时加入双精度世界有向体积和本配方identity transform契约；反例必须由世界负体积专用字段拒绝，而不只靠变换限制。修复之后需重跑全部真实模型与坏例，再以正式资产SHA记账；不借中间通过报告。

### 原始mesh不等于带修改器的显示几何

检查器作者进一步指出raw `ob.data`不评估modifier/shape key。纯模型契约现在明确拒绝这些状态，以及额外非mesh对象、constraint、parent和动画/driver。真实Solidify与Shape Key反例保持raw顶点/面SHA不变、其它几何缺陷项为空，仍由对应state reason拒绝。不是宣称检查器能验证任意evaluated Blender场景。最终18项包括12个native与6个GLB。

## 6. 厚度与渲染的诚实边界

法向偏移公式保证名义中心线站点的t，但离散弦面中点约为`t cos(Δθ/2)`。Folio对应顶底顶点范围约2.9999855–3.0000103mm，边中点约2.9995288–3.0000061mm；没有抹平这点数值差异再说“处处精确等厚”。实际采样点数、前后接地跨度都记入原生报告。

48→128同分辨率预览的平面裁片高频残差下降，之后选择256采样上限/960²；不是默认堆1024。该残差只是图像指标，不是无偏噪声估计。无可用降噪器，因此未声称降噪；金属上的残余颗粒也没有被重新包装成拉丝贴图。

## 7. 下一轮可复用的方法

1. 先保留低采样首版，再将少量形体问题变为明确参数变化，固定相机比较。
2. 圆角须说清是在平面轮廓、截面还是所有边方向；不能仅凭一条亮边叫倒圆完成。
3. 法向偏移的解析厚度和离散网格的局部实测厚度要并列，不混称。
4. 数值容差要联系实际三角尺度与顶点量化精度；双精度后处理不能恢复未保存的精度。
5. 几何检测必须说明坐标系；局部正体积不自动等于世界朝外。
6. 每个反例要求它要测试的专项字段命中；整体拒绝不代表所有专项都覆盖。
7. 原生、GLB字节、CPU渲染、浏览器状态、GPU实时、制造性能是不同验收层。

## 保留的不足

- 形体族受限于平面中心线、固定宽度控制规律，不是任意曲面/任意折板生成器。
- 端盖厚度边仍硬；当前不以更多倒角和装饰继续堆复杂度。
- 前托/后足为金属数字面接地，没有防滑垫、紧固机构、载荷/倾覆/书本适配验证。
- BVH排除共享顶点三角；邻面非共面折叠不具备完整独立证明。全顶点恒等契约是本配方保护，不是泛用解法。
- GPU、WebGL实时画面、动态闪烁、真实iPhone未验，禁GL安全设置未更改。制造与人体工学未验。
