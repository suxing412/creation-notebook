# 002 网页 v2｜材料杂志，而非观察台换肤

## 独立设计任务
以暖纸、陶瓷灰绿与铜色组织“轮廓 → 翼面体块 → 接合不足 → 三视图证据 → 制作档案”。保留明亮编辑式阅读，与 001 暗色聚光明确区分。本轮没有更改模型字节。

## 成品之后的对标与评审
参考 [Apple AirPods Max 原页](https://www.apple.com/airpods-max/) 的组件说明与 [teenage engineering OP–1 field 原页](https://teenage.engineering/products/op-1) 的细节、技术信息分层，借鉴“具体细节为什么重要”，不抄品牌视觉、不使用外部模型或图片。参考证据是原作者网站的可读文本和图片描述，未宣称实际体验动画。

旧版虽然可以滚动，但手机把下载和制作复盘一并藏在“调节”里；正文又小又浅。评审建议先改内容可达性，再追求装饰精度。

## 已改
- 将下载与两类复盘彻底移出调节区，常显在正文末尾；页首“下载与复盘”直达，不必猜测设置入口。品牌返回总览。
- 添加三个阅读节点及真实侧、顶、正视图，分别解释翼缘、铜脊/体块、接合局限。每幅图可直接打开原图，alt 描述其观察任务。
- 明说尾部仍是独立嵌入组件，不冒称制造级连续曲面。三视图整体图版仍保留，防止碎片化细节取代整体判断。
- 加深主弱文字，提高主体 14–15px、操作 13px、主要按钮最小 44px。细英文不再承担唯一关键信息。
- 实时工具折叠为次级工具；无能力时说明并禁用。手机展开区放入文档流，不悬浮遮住图片；源文件路径不受它控制。
- 增加跳至内容与清晰焦点，Escape 关闭调节区时必要地归还焦点；保留减少动态与真实静态降级。

- 新增画布方向键环视替代拖拽；操作时停止自动环视。只在实时健康状态处理方向键，静态图模式不拦截页面滚动。已检查语法，尚未以 GPU 实际验证。

- 浏览器复查发现手机头部打开调节后工具在屏幕下方，产生无响应错觉；已补打开后聚焦实时工具 summary 并滚入视口，关闭时仍归还触发器。

- 断 JS 复查发现旧加载文案不会结束；已用 noscript 专用样式移除加载层、实时画布和调节按钮，并在图旁说明静态模式。正文与源文件链接保留；沙箱中的链接可达不代表实际文件下载已验证。

## 检查证据与边界
- JavaScript 语法通过；主文档 ID 无重复；本地资源链接存在，图库设计案例及返回路径待集成确认。
- GLB、Blender 的 SHA-256 与修订前公开文件逐字节一致。
- 主弱文字 `#56645a` 对纸底 `#eeece5` 计算对比 5.28:1，仅为该纯色色对，非全站认证。
- 集成端已用真实浏览器 iframe 检查 002 容器 390/320/768（实际内容宽 375/305/753）：无横向溢出、可纵向滚动、静态降级正常。在 390 容器中关闭调节区，点击常显“下载与复盘”已到达真实档案按钮。未新增真实手机、读屏或 GPU 测试；200% 放大、完整键盘与读屏仍待确认。iframe CSS 视口不冒称真机。

### 修订后浏览器复查

002 的 390 容器：Enter 打开调节后，summary 顶部 408px、底部 456px，位于 844px 高视口内；常显档案链接实测高 60px。 从 summary 按 Escape 后面板关闭，焦点回到 panel-toggle。

另用 `sandbox="allow-same-origin"`、不允许脚本的 iframe 复查：加载层与无效调节按钮隐藏，真实主图已加载（001 自然宽 900px；002 为 1200px），档案可见，静态说明存在。这验证无脚本展示和链接可达，不代表沙箱内文件下载、真实手机或 GPU 通过。

## 尚不足与下一次
新增卡片使用既有完整视图，并非专门为铜脊和尾根拍摄的微距；正视图不能独自证明尾根几何连续性，必须结合模型检查。下一轮应补一幅真正解释尾根搭接的近景，而不是继续堆叠诗意文字。先保证没有 WebGL 的访客也能读完整证据，再谈更复杂转场。

基线参考：[W3C 对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)、[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。44px 为项目触控目标，非 WCAG AA 全部控件的通用硬门槛。
