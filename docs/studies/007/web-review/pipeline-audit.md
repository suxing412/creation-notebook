## CRC与冻结失败控制

第一阶段导入套件的 **12项** 独立重跑通过，包含提供正确外层SHA后破坏内部CRC的反例：整包读取校验失败，旧目录不变。合法微型fixture在完成检查后才替换旧目录。

冻结入口的失败控制故意缺少首项测试文件；观察到预期非零退出、旧冻结标记被删除，且没有自产生缓存。投影与导入测试另以直接Python入口完整执行，均返回0、未产生pyc。**这些不等于完整最终包成功冻结。**

## 边界

所有微型清单、占位报告和坏ZIP都只是临时测试fixture，不作为模型或浏览器证据发布。第一阶段没有验证最终模型ZIP。第二阶段增加了实际原包与导入字节身份核对，见下文；仍没有重跑模型几何门禁，也没有验证最终网页完整冻结、原生浏览器、GPU、真机、200%缩放、读屏或制造性能。

导入锁用于发现parity／覆盖层的误改和集合污染，不是数字签名；不声称能抵抗同时修改源码与锁的行为。最终资产仍须按最终输入重新检查并绑定身份，不能借本次隔离回归放行。
