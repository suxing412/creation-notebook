# 001 网页 v2｜暗色聚光，不再锁住阅读

## 独立设计任务
在深蓝黑、金色与青绿色的展台中，建立“完整轮廓 → 核心细节 → 检查证据 → 源文件”的路线。模型观察是其中一项功能，不是网页全部内容。本轮未修改模型文件。

## 成品之后的对标与评审
阅读了 [Apple AirPods Max 原页](https://www.apple.com/airpods-max/) 的整体、近看与组件说明次序，借用“一幅细节解释一个问题”的组织方法，而不复用其图片或动画。此处依据原站可读文本与图片说明，不声称体验过原站动画。

旧版存在整页禁止滚动、固定视口高度、8–10px 关键文字和下载藏在移动调节区的问题。旧版审查结论保留在整体网页评审；以下只记录实际落地修订。

## 已改
- 暗色展台保留；固定高度主区改为正常文档流。1100px 以下减少主视觉列数，760px 以下纵向阅读，页面可滚动。
- 主体说明提升至 14–15px，按钮 13px、主要按钮最小高 44px；此为项目设计目标，不宣称全站无障碍合规。
- 下载、建模检查、专业对标及网页复盘进入常显档案区，和模型调节彻底分离。新增返回总览、页内路线和跳至内容。
- 无效实时工具收进原生折叠区并说明不可用；不删除错误提示，不把静态图标为实时。实时可用时自动展开工具。
- 新增真实修复版核心近景：明确指出宽肋遮挡晶核。拓扑修复与审美完成分开评价。
- 移动调节区展开时占据正常文档流，不覆盖模型；Escape 关闭后，焦点若在面板内则归还触发器。减少动态偏好继续禁止自动环视，并取消新增 CSS 动画与平滑滚动。

- 新增画布方向键环视替代拖拽；操作时停止自动环视。只在实时健康状态处理方向键，静态图模式不拦截页面滚动。已检查语法，尚未以 GPU 实际验证。

- 浏览器复查发现手机头部打开调节后工具在屏幕下方，产生无响应错觉；已补打开后聚焦实时工具 summary 并滚入视口，关闭时仍归还触发器。

- 断 JS 复查发现旧加载文案不会结束；已用 noscript 专用样式移除加载层、实时画布和调节按钮，并在图旁说明静态模式。正文与源文件链接保留；沙箱中的链接可达不代表实际文件下载已验证。

## 检查证据与边界
- JavaScript 语法检查通过；主文档无重复 ID；除图库负责生成的设计案例链接及集成后返回入口外，本地链接目标存在。
- GLB、Blender 文件 SHA-256 与修订前公开版完全相同；近景 PNG 只去除文本元数据，解码像素完全一致。
- 主弱文字 `#a0b1b2` 对纯底 `#0c171c` 计算对比 8.16:1。这是指定色对检查，不是渐变、图像上文字或全站的自动合规证明。
- 集成端已用真实浏览器 iframe 检查窄宽与短桌面：001 容器 390/320/1280（实际内容宽 375/305/1265）均无横向溢出，纵向可滚动，静态降级正常。发现窄宽英文标题连字后已补空格。200% 放大、完整键盘路径、读屏与真机仍待逐项核验；真实实时闪烁、手机触控未验。

### 修订后浏览器复查

001 的 320 容器：Enter 打开头部调节后，summary 顶部 277px、底部 343px，位于 600px 高视口内。 从 summary 按 Escape 后面板关闭，焦点回到 panel-toggle。

另用 `sandbox="allow-same-origin"`、不允许脚本的 iframe 复查：加载层与无效调节按钮隐藏，真实主图已加载（001 自然宽 900px；002 为 1200px），档案可见，静态说明存在。这验证无脚本展示和链接可达，不代表沙箱内文件下载、真实手机或 GPU 通过。

## 尚不足与下一次
核心近景呈现了缺陷而未修复宽肋；这必须回到建模环节。网页仍有观察工具、长错误说明与图像之间的空间竞争，须在实际窄宽复查中观察，而非以 CSS 媒体查询存在代替验收。下一轮优先测缩放重排和键盘路径，再优化错误说明长度。

基线参考：[W3C 对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)、[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。采用方法，不声称已完整满足规范。
