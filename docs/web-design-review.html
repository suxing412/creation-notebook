网页设计复评：让页面成为作品，而非模型的包装

评审日期：2026-11-01。范围：001 悬浮圣器、002 潮翼、003 玄瞳、004 岬界及总览的当前版本。

评审口径

本轮是四份既有网页的补充评审，不是四份全新网页的完成证明。已直接读取页面结构、样式和有关交互代码，并在成品之后联网阅读五个原作者／品牌网站。项目已有桌面静态降级截图检查；本报告未新增浏览器操作测试。以下明确区分代码事实、设计判断、改进提案和待验项目。

尚未验证：真实手机、屏幕阅读器实际播报、实时 WebGL 画面、运动时深度闪烁。响应式规则存在不等于手机验收通过。原站参考采用可读取的正文、控件标签、图像描述和内容次序，不声称实际体验了其动画、画面帧率或全部视觉布局。外部图片不复制进作品。

优先级：P0＝内容不可到达／误导状态；P1＝可读性或任务路径明显受阻；P2＝叙事与精致度。下文均为评审时状态；修订后应另列“已改＋证据”，不可把建议改写成已完成。

五个参考，五种可借鉴的方法

1. Apple AirPods Max 产品页：由整体到局部。 页面可读取到主标题、亮点段、近看入口、颜色选项，随后把旋钮、头梁、耳垫分别配给说明。借鉴的是一个视觉主题对应一个解释，不照搬其宣称或滚动特效。适用于 001 主视觉层级、002 材质章节。证据：原页内容和图片替代描述；未验证实际转场。Apple 原页

2. teenage engineering OP–1 field：技术性格来自具体细节。 原页依次解释显示屏、机身厚度、背部结构，最后另列技术规格和指南。可学习“细节图＋它为什么这样设计”，而非把参数挤进第一屏；不采用原页的夸张营销话术。适用于 003 控件及机构解释。OP–1 field 原页

3. David Chipperfield Architects / Neues Museum：空间和证据共同叙事。 原页有项目地点、年代、设计缘起、楼梯与材料的解释、平面图图注及可展开的资料／署名。由此推导 004 应呈现路径和空间关系，而不仅是相机朝向按钮。此处读取了内容，不把文字图注当作已经看过整套建筑图。Neues Museum 原页

4. Snøhetta Projects：作品与状态可分辨。 原页提供 Grid/List/Map、学科、类型、地点与进度筛选，条目具有名称和年代。借鉴分类和状态，不在四件作品时堆满筛选器。用于总览区分“常规双产出／融合练习”及已验、待验。Snøhetta 项目库

5. Bruno Simon：空间本身就是导航。 作者原页明确邀请驾车探索作品集，列出移动、交互、地图、复位、画质和多种输入方式。可确认它的设计意图是通过空间探索访问内容，而非仅旋转一件模型；本轮未实际驾驶或验证其渲染。这是融合轮的方法参考，不复制车辆、地图、资产或品牌表现。Bruno Simon 原站

这些是有对应方法的专业参考，不是“全球最佳网站”排名，也不是模仿画风的理由。

001 悬浮圣器：聚光与视觉层级

独立网页目标： 深蓝黑与金玉色构成展台；让访客先读清一个轮廓，再选择观察，最后追溯制作。不要用四套控件和英文小字共同争夺视线。

已经具备： 标题、模型、观察台三分区；显式焦点样式；真实离线主图；错误时禁用不支持的控件；桌面观察台已有纵向滚动；移动调节层已有展开状态和 Escape 关闭逻辑。

代码事实及问题：

P1：页面 overflow:hidden，主区有固定视口减法及最小高度；短屏或文字放大时仍有页脚、标题／内容被裁的风险。控制区局部滚动没有解决整页可达性。

P1：关键信息大量使用 8–10px；网格统计颜色与纯色底近似对比仅 3.97:1。背景实际有渐变，最终须逐区域复测，不能把这个单点值当全页结论。

P1：品牌链接指向当前页，不是总览；阅读路径容易成为死胡同。

P2：主体采用约中间一半宽度，标题和不可用控件仍占稳定空间；静态模式应突出真实图版，不能继续像一台故障的控制台。

具体修订： 保留暗色戏剧性，不改米色。首屏只保留名称、主图、模式标记与“观察／制作记录”两条路径；短屏和缩放时自然滚动。主体说明至少 14px，操作文字至少 12px；辅助英文可小，但不可承载唯一信息。静态模式把不可用实时选项收进带原因的折叠区。增加常显“返回总览”。以 Apple 的整体→局部方法增加一幅核心细节图和一句观察重点，而不是增加装饰标题。

验收： 1280×600、768×600、390×844、320 CSS px 宽及 200% 文字放大分别检查；标题、下载、返回入口都能到达；键盘不困在面板；静态模式主图无遮挡；记录同机位前后截图。未通过不得写“全设备适配”。

002 潮翼：编辑节奏与渐进披露

独立网页目标： 以暖白陶瓷与铜色为材料杂志，建立“轮廓→翼缘厚度→尾根搭接”的三段阅读，不成为 001 控制台换肤。

已经具备： 可滚动正文；大主图、三视图与图注；主图包含真实渲染说明；原文件可下载；焦点样式和减少动画规则存在。

代码事实及问题：

P1：移动布局隐藏整个观察台，下载和制作复盘都在其中；按钮却只叫“调节”。这让看源文件的用户必须猜测一个不相关入口。

P1：正文／说明 #737a70 对纸底 #eeece5 约 3.74:1；关键说明又多为 10–11px，轻盈变成了费力。

P1：品牌仍为自链接；三视图有内容，网页本身的设计过程却没有独立入口。

P2：主图后直接三视图，缺少材质和形态如何变化的编辑逻辑；默认展开下载清单与主图竞争，手机却相反被隐藏。

具体修订： 把下载与两类复盘移到正文末尾常显区域，与调节层彻底分开。主视觉后增加三张短图文卡：翼缘／铜脊／尾根；每卡一幅实际图、一句形态判断、一条尚未解决之处。桌面实时控件默认收为次要工具。加返回总览。提升正文色深和字号，不以加粗全部文字补救。参考 Apple 的局部解释和 OP–1 的细节理由，保持留白但缩短无信息空白。

验收： 手机宽度下无需打开“调节”即可下载及读复盘；禁用 JavaScript 时主图、三视图、正文、下载仍可读；三张卡视觉顺序与文档顺序一致；普通正文对比至少 4.5:1；每张图有针对内容的 alt，非“图片 1”。

003 玄瞳：可理解的控制与状态

独立网页目标： 深色精密仪器面板；用户能随时回答“现在是什么状态、我能做什么、这证明了什么”。视觉精度来自状态秩序，不靠更密的刻度。

已经具备： 三个离线状态可在实时模块失败时独立切换；按钮选择、角度读数、图像文字同步；非实时模式有明确标记；已有“转角不是 f 值”的机构说明，已有非完整联动的限制；图版、结构展开区、检查复盘、源文件齐全。主要弱文字对面板色近似 6.74:1，不应误报全站都有同样对比问题。

代码事实及问题：

P1：转角与 f 值的边界已有，但在面板较低位置；应在角度控件附近简短复述，避免用户先形成错误理解。不是缺少免责声明，而是信息距离太远。

P1：状态切换文本虽更新，未见状态名自身的 live region；不能由此声称读屏已充分播报。

P1：结构展开 summary、画布不在自定义焦点选择器中；浏览器默认可能仍有焦点，需实际检查，不可直接判“无法键盘使用”。

P2：手机先经过高约一屏的舞台再到状态按钮；连续观察的手眼距离较远。多个禁用区仍占面板中段，弱化了真正可用的三个按钮。

具体修订： 三态选择贴近图像下缘，手机常显但不遮图；角度旁显示“叶片转角，非 f 值”；状态名设置礼貌播报，避免滑动时高频播报。非实时控件折叠为说明，保留可用状态。为结构展开加清晰焦点和展开反馈。采用 OP–1 的“一个组件一条解释”，配一幅支点细部而非重复三状态主图。

验收： 键盘完成中间→收拢→展开→结构展开，选中态、读数、alt 与图像一致；失败模式不出现可点击但无效的操作；减少动态偏好时不自动环视；有硬件环境再独立验实时切换，不将离线三图测试计为实时验收。

004 岬界：建筑空间叙事

独立网页目标： 以冷灰白、海雾绿和青铜建立建筑章节，讲述“抵达岩岸→登阶→穿门→观测”的路径。它应是空间阅读，而不是给 002 的暖纸换成冷纸。

已经具备： 主图之后可切换日光、薄暮、正交视角及门廊；状态区说明实时能力；名义尺度和非工程设计边界明确；原文件及检查入口常显。

代码事实及问题：

P1：七个按钮同级混合时间氛围、观察方向与空间细节；用户不知道应先看哪个，也看不出改变的是光还是相机。

P1：普通说明 #657774 对底 #edf0e9 约 4.10:1；状态说明只有 11px。按钮初始只有日光显式 aria-pressed=true，其他按钮宜初始化为 false。

P1：canvas 没有可读名称和键盘入口；需明确实时观察操作的可访问替代方案。

P2：主视觉后只有两段概述，缺少尺度／路径证据。没有走向、门洞和露台的关系，就无法称为建筑叙事网页。

具体修订： 主按钮改成“抵达／门廊／观测”三个章节并关联真实渲染；日光／薄暮另列“光照”，正交视角进入“检查视图”。为每章写一个空间问题和一幅相应视图；可加原创俯视路径示意，但标明不是施工平面。前后修复图置于证据章节，不能让错误旧图充当当前效果图。正文加深。桌面宽幅／手机竖排构图分别评估，不强行把全部画面裁为方形。

验收： 不看模型代码也能辨认入口、楼梯、门廊和观测点；切换章名、图像、图注与选中态一致；加载失败保留上一张有效图并提示；图像原图链接可达；路径说明不包含未经验证的建筑合规主张。

总览：从单一模型目录到双轨作品集

保留： 清楚的编号、真图、面数与已改／待改、返回链接、跳至内容、减少动态规则。不要把几何检查数字当审美分数，不以面数高低排名。

必须改：

每轮卡片显示两个产出：“3D 作品”与“网页作品”；再提供“建模复盘”与“网页评审”。网页作品链接指向实际可访问设计；设计案例说明不是网页成品替身。若两种入口进入同一页面不同区段，明确标注，不假装两份不同实现。

每张卡写一句独立网页目标和版本，如“001 聚光层级／网页 v2”，并链接改前后证据。没有落地的新设计只能标“评审完成／修订中”。

普通弱文字当前约 4.15:1，应加深后逐区域检查。首张作品图不必懒加载；其他图保持尺寸预留和延迟加载。此项是加载策略建议，未测 LCP，不报性能成绩。

四件时先用常规／融合分区，不造复杂筛选器；后续超过八件再考虑按主题与技能筛选。参考 Snøhetta 的分类逻辑，不复制其多重导航。

新节奏：两轮常规，再一轮融合

每个常规轮均交付建模＋独立网页设计，再进行联网对标、两类评审、修订复查与复盘。每两轮之后增加一轮 Three.js 三维网页融合练习。已有 001–004 属于常规练习，不把 003 的模型观察台改名冒充融合网页。

F01 提案：轨与翼 · 空间索引

对应常规 001／002 补齐后的第一融合轮。目标是让三维空间承担网站的信息架构与导航，而非大画布周围堆 HTML 按钮。

三个原创空间节点：序厅、星轨档案、潮翼档案；两个作品各有世界坐标位置与内容锚点。选择导航触发相机移向对应节点，同时呈现作品、网页说明与复盘入口。

首屏提供“进入空间”和常显“阅读列表”。键盘／点击选择目的地即可，不要求游戏驾驶技巧；不借用 Bruno 的车或场景。

空间连接用轨道与流线呼应两件作品；不加无关粒子、音效或强制滚动劫持。基础 HTML 链接提供全部信息，Three.js 加强空间理解。

DOM 导航、URL hash、相机目的地与当前章节状态同步；浏览器后退可回上一节点。减少动态模式直接跳转，无过渡。WebGL 不可用时保持等价三章列表与真实图，不显示假三维运行标记。

设计验收必须包含：每一节点都能抵达；可退回总览；键盘不困住；断资源仍可阅读；真实 GL 环境验证相机穿越、对象遮挡与帧率后才标实时通过。性能预算先设项目目标并实测，不预先宣称达标。

F01 尚为设计任务书，不是已完成作品。003／004 的第二融合 F02 应等对应网页复查后再开始，避免为凑次数跳过反馈。

共通复查与下一轮记录模板

1. 产出：模型版本、网页版本、真实预览及可访问链接。

2. 对标：原作者 URL、实际读取／看见的内容、不可见部分；至少一条具体差距，不只写“高级感不足”。

3. 修订：问题→改动→相同条件前后截图→验证结果。

4. 可用性：320／390／768／1280 宽度、矮屏、200% 放大、键盘、断 JS／断模型资源、减少动态；区分自动检查、浏览器观察和真机测试。

5. 残留：分别列几何风险、视觉不足、网页交互缺口；没有证据不标绿色通过。

6. 下一步：只带入一到两个主要技能缺口，不每轮全面换皮。

本文采用普通文字对比至少 4.5:1 作为复查基线；44px 为本项目主要触控目标建议，不冒称 WCAG AA 一律要求 44px。WCAG 2.2 的目标尺寸最低条款是 24×24 CSS px 或满足相应例外／间距条件。重排基线包括 320 CSS px 宽的内容可达性，复杂二维展示本身有例外，但周围导航与正文不因此豁免。W3C 对比说明 · 目标尺寸说明 · 重排说明

本轮总结： 当前从 001 到 004，已从“全屏展示台”走向更诚实的静态降级和证据展示；欠缺的是阅读任务、网页自身的设计版本和真正空间化的信息组织。下一步先修 001 的可达性、002 的内容路径，再以 F01 检验三维是否真的帮助导航。更漂亮不是更多装饰，而是每种形式都帮助人理解作品。
