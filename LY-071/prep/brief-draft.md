## 3. 实测结论（脚本见 §7）

### 3.1 两件的原点确实不同
- **礼堂 A**
  - 本地 y=0 是**台面顶**：向上面 1,302.4 m²，即 36×36 台面加 4 个顶级踏面（各 0.4×4）。
  - 台基底和踏步脚都在 **y=-1.2**，向下面 1,334.4 m²。
  - 四个方向各有一道轴向踏步：宽 4.0 m（侧向 ±2.0），6 级，每级高 0.2 m、深 0.4 m。台缘在 r=18.0，最低一级外缘在 r=20.4。
  - 三档的 earth 节点完全一致（588 三角形，档间偏差 0），三档都保留六阶。
- **围护 L**
  - 本地 y=0 是**墙底**，墙顶 y=2.0。
  - 它只是**一个象限**：+x/−z（东北）一角的 L 形土墙，中心线在 |坐标| = 68.0。
  - 底厚 0.70 m（67.65–68.35），顶厚 0.50 m（67.75–68.25），两侧各收分 0.10 m。两臂在 x=4.0 和 z=-4.0 处截止。
- 礼堂不符合 LY-005 的新资产规则（本地 y=0 = 接地面）：它的接地面在 -1.2。这一点要写进端口，不能重新烘网格。

### 3.2 试配变换已实测锁定（全部为 C 工程值）
组原点 O 取试配分块里围护节点的平移：O = glTF (2183.6731, 0, 938.776)。它等于证据标记 `ritual_biyong_B` 的 (east, north) = (2183.673, -938.776)。这个点只来自示意图数字化（B 类），城市位置**未准入**。
- 礼堂 A 三个节点相对 O 的偏移都是 **(0, +1.2, 0)**，没有旋转。公开 LOD0 平移 +1.2 后与试配逐点比对，Hausdorff ≤ 0.119 mm，属于城市尺度下的 float32 误差。平移 0 或 2.4 时都偏 1.2 m。
- 围护 A-v2 = **公开 enclosure-L-LOD1 按 R_y(0/90/180/270°) 复制四份**。双向 Hausdorff ≤ 0.133 mm，三角形 9,488 = 2,372×4。只放一个 L 时，试配到 L 的偏差为 154 m。
- 组内接口：
  - 礼堂踏步脚 y=0 = 围护底 y=0 = 试配岛顶 y=0。
  - 四个轴向开口宽 8.0 m（±4.0）；礼堂踏步宽 4.0 m，与开口同轴居中。
  - 踏步外缘到围护内墙脚的净距是 **47.25 m**（20.40 → 67.65）。

### 3.3 换到 LY-006 冻结的框架 `local:biyong`
LY-006 registry v1（zones.json 6b3595ac…）把 `local:biyong` 定为「hall A origin」，即礼堂 A 的本地原点（台面顶中心，y=0）。因此制作期按这个框架写：
- N_hall = **I**
- N_encl,k = **T(0,-1.2,0)·R_y(k·90°)**，k = 0..3
- 试配组原点 O 在 local:biyong 里位于 (0,-1.2,0)

§3.2 的组框架写法（原点在地面，礼堂 +1.2）和这里的写法只差一个整体平移，**两种只能选一种**。选定一种后，另一种的平移不能再叠上去（负例 N2）。

冻结端口 `biyong:hall-enclosure:ground` v1：
- producer 和 steward 都是 LY-071，consumers 是 LY-072、LY-073。
- 容差：position 5 mm，elevation 2 mm。
- local、world、nodeMatrix 目前都是 null，由本席位交付时填写。
- 实测值：local:biyong 中 y = **-1.200**。礼堂底、踏步脚、围护底三者一致。

### 3.4 真实缺口（带数字）
1. **同原点直叠会失败（负例 N1）**：两件都按单位矩阵放时，礼堂脚比围护底低 **1.2 m**。而两件之间的三角形交叠数是 **0**（9 组 LOD 组合全是 0），碰撞检测发现不了这种错叠，必须用高程端口来查。
2. **重复施加（负例 N2）**：+1.2 施加两次时，礼堂脚悬空 **+1.2 m**。
3. **试配的 LOD 标签与实际不符**：试配节点名叫 `C_BIYONG_ENTRY_LOD0`，但其中的围护是 **LOD1 几何**（每象限 2,372 三角形）。公开的围护 LOD0 每象限 17,608 三角形，四份共 70,432，从未参与试配。三档对应表必须重写，不能沿用试配里的标签。
4. **公开卡只有一个象限**：完整围护需要 4 个实例。
   - 城景的 researchModels 机制只加载一个资产、用单位矩阵：city-renderer.mjs:645 `focusResearchModel` 调用 `rebuild(id, new Set([id]))`。它无法表达「礼堂 + L×4 旋转」这 5 件的组合。
   - 出路一：由 LY-100 扩展为多节点研究组。
   - 出路二：另交一个预合成 GLB，其 N 必须是单位矩阵。但这条路有个问题：预合成 GLB 里的围护会落在 LY-071 写入区 `LY-071:write:001` 之外。这个写入区是 [-20.4,-1.2,-20.4]–[20.4,0,20.4]，只覆盖礼堂台基，而围护在 |68| 处。所以出路二要先请 LY-006 出 v2；在那之前只交出路一用的 assembly.json，直接引用原 GLB 的字节。
5. **LY-006 v1 的辟雍区盒与实测布局不符**（`zone_check.py` → `zone-check.json`）：
   - LY-072 的跨水走廊在 x 20.4–30.0，LY-073 的岸缘和到达地面最远到 x=40.0。这些区盒全部落在**围护以内**（内墙脚 67.65），位于礼堂踏步脚和围护之间的旱地岛面上。
   - 试配里的跨水板在 r **69.8–78.2**，水符号环在 r 70–78，都在围护以外。
   - 区盒最外端到试配跨水板差 **29.8 m**，到水环也差 29.8 m。区盒内没有水，跨水件放在那里跨不过任何东西。
   - 区盒与围护的 8 条臂没有 AABB 相交。这是逐臂计算的结果；如果用整个 L 的包围盒算会出现假阳性。区盒与礼堂只在 x=20.4 处面接触。
   - LY-006 的 brief 自己写了「辟雍跨水与岸缘（LY-071 的变换还没锁）…保守划分…申请 registry v2」。本项的实测就是申请 v2 的依据。
6. **组内地面无人负责**：公开卡没有地面。礼堂外 r 20.4–67.65、围护外 68.35–70 的地面，在试配里只靠 `biyong-layout__A_island` 替身（140×140 m，y -1..0）。LY-006 v1 中 LY-071/072/073 三席的 ownsGroundPieces 都是空的。岛、水、跨水归 LY-072/073；台基和围护之间这块地坪的归属要由 LY-006 v2 明确。
7. **继承的网格缺陷**（`manifold_check.py`，焊接容差 1e-5 m）：
   - 礼堂 earth 节点三档都有 **20 条非流形边**，开放边为 0；tile LOD1 有 7 条，timber LOD2 有 2 条。
   - 围护三档焊接后都是闭合流形（0/0）。
   - 本项不改几何，只把这些计数记为继承基线：安装前后计数必须不变，也不能声称「整体无缺陷」。LY-072 的 prep 独立测到了同样的 20 条。
8. **城市位置未准入**：试配是按 B 类示意点烘进世界坐标的，没有经过 LY-004 配准。城内地面族高 0.20/0.21（LY-005），而试配地面在 0，将来入城会有 0.20 m 的高差需要写进端口。本项只交局部变换，world 和 cityMatrix 保持 null。
9. **LOD 差**（只做比较）：围护 LOD0↔LOD1 的表面偏差最大 14.6 mm（夯土起伏），LOD1↔LOD2 最大 3.1 mm。礼堂 LOD0→LOD1 最大 59.6 mm，LOD1→LOD2 最大 324 mm，偏差只出现在上部木作和瓦，earth 节点为 0。
