## 一、协作与发布流程（现行）

**分工**
- 伊苏里亚：出内容（模型、卡片、考据）。
- Claude：维护网站、做质量评审，任务池里也做建模，担任 LY-100 唯一的城景合并席。

两边的模型走同一套评审和反方复核，谁的作品都不自评通过。

**提交一件资产**
1. 文件放进 `docs/library/<分类>/<id>/`，写卡片 `<id>.asset.json`（规范见 `docs/asset-spec/README.md`）。
2. 运行 `python -I lab/tools/build_assets.py --check`，有错误不提交。
3. 推到 main。部署会自动瘦身：GLB 做 meshopt 压缩，PNG 转 WebP。**仓库里留原件，提交时不用自己压缩**。
4. 例外：`docs/cities/` 和城景点名的模型原样发布，因为城景会核 SHA-256，还会按节点名替换模型。它们要变小，就自己用 `gltfpack -cc` 压缩，并同步更新登记的哈希。

**收批（带新模型或改动模型的批次必须做）**
- 提交 `docs/asset-spec/batches/rYYYY.MM.DD-N.json`，内容是 `{"tag","summary","sources"}`，推到 main。
- 工作流会在这次提交上打附注 tag，建好同名 Release，放入这一批的 GLB 原件和 `originals.json`。
- 你已经这样收了 05-5～05-8。

**源文件**
- 不进仓库，放进本机的 `D:/GitHub/creation-notebook-待传/<tag>/`。
- Claude 运行 `upload_sources.py`，上传到对应 Release 并核对 SHA；核过的本地文件挪进 `D:/待删-*`，不删除。
- 制作人已授权你用翻天印，只往这个文件夹里写。

**网站只负责展示**
- 详情页不提供下载，原件一律到 Release 取。
- 想知道某件资产的原件在哪：先找它最近一次改动属于哪个批次，再到那个 Release 下载。

**收到 Claude 的评审之后**
- 结论是「判断 + 证据」，按严重度排序。
- 内容类问题由你处理；网页类由 Claude 处理。
- 觉得判断不对，直接写出来，Claude 会复核。

## 二、建模工作流优化（来自全库评审）

总体判断：风格统一，几何卫生好，研究诚实度高。失分主要集中在少数几个**模板缺口**，它们跟着复用扩散到几十张卡片。所以要先改模板，再按派生关系批量重建，而不是一张张修卡。

### A. 先改模板（影响面最大）

| # | 问题（受影响卡数） | 改法 |
|---|---|---|
| 1 | 檐墙砌不到屋面，墙顶和板底之间有 0.2–0.5 m 通长空槽；殿堂更大，玉堂 0.55 m，明堂约 1.4 m（16） | 檐墙砌到板底，或补檐檩、椽头、封檐板。风格工具库目前也是照原样复刻这道槽，要不要补请你和制作人定，建议补 |
| 2 | 柱头直接顶屋面，缺栌斗/斗栱、阑额、檩椽这一层（27） | 建东汉木构承托件库。LOD0 必须挂上，LOD1 至少留栌斗和椽头。建模时按「台基→础→柱→栌斗→阑额→檩→椽→望板→瓦」逐层打勾 |
| 3 | 屋面收头缺失：没有正脊、垂脊、瓦当、博风（29） | 让屋面生成器必须输出脊筒瓦（含两端收头）、庑殿垂脊、素面瓦当、悬山博风 |
| 4 | 瓦面看起来像波纹板或平板，LOD1 把垄抽稀（18） | 用统一的「汉瓦屋面」生成器：板瓦凹弧＋筒瓦半圆，垄距 0.20–0.25 m 铺满整坡。LOD1 保持同一垄距，不许抽稀 |
| 5 | 城门门台是几块分开的土墩托木楼板，门道直通台顶，四壁无收分（10） | 以旄门的排叉柱、替木、过梁门道为样板重做模板：墩台连成一体、四面收分，门扇、门砧、门限为必选件 |
| 6 | 门洞只留空口，没有门扇、门槛、门砧，院门没有门屋（10） | 做一套门构件，带开、闭两种姿态。通行检查用开门姿态跑，不要删门 |

### B. 导出前的自动检查（不通过不导出）

可以在 `LY-008/source/ly_check.py`（已带负例）的基础上扩展。

| 检查 | 规则 |
|---|---|
| 墙—屋面相接 | 沿墙顶每 5 cm 取样，净空大于 2 cm 的连续段列出来，并出一张标注图 |
| 构件接触 | 逐对检查屋面↔檩梁、脊↔屋面、楼板↔梁、柱脚↔础、器物↔台面、门扇↔门框；间隙或穿插超过 1 cm 就报。展示用的故意留缝另出文件，并在卡片里说明（22 张有悬空或留缝） |
| 承托链 | 柱顶往上 3 cm 内必须先碰到木构件；跨度超过 4 m 的屋面下方必须有梁或檩 |
| 收头 | 每个坡面的最高边必须被脊件盖住；檐口筒瓦端面必须封口 |
| 色板 | 维护一张「材质名 → sRGB 均色 → 贴图 SHA」登记表，偏差 ΔE 小于 3；LOD2 的平涂色由 LOD1 贴图均值换算得出，不手填（12 张两套色板混用、切 LOD 跳色）。另外，夯土用黄土色还是灰米色，请先定一个口径 |
| 双面 | 材质库默认开启背面剔除，只有幕布、薄片保留双面（351 个 GLB 中有 348 个的材质全部是双面） |
| 共面与内部面 | 重叠面积超过 1 cm² 的面要合并，或错开至少 2 mm；合批后删掉背靠背的内部面 |
| 展台分离 | 展示用的地面、背景幕、展台不进主体 GLB；非主体部分的包围盒不得超过主体的 1.5 倍（6 张） |
| 预算 | 单体近景不超过 5 万面且不超过 5 MB，街区中景不超过 3 万面，远景不超过 5 千面；LOD1 约为 25–40%，LOD2 约为 5–10%，各档必须从 LOD0 派生（27 张 LOD 链不成梯度） |
| 近乎纯色贴图 | 像素标准差小于 4 时提示：要么让贴图带上真实信息，要么改用常数色（43 张卡上，同一份约 966 KB 的近乎纯色贴图在每个文件里各嵌一份） |

### C. 交付清单

- **出图**（34 张卡的图集与封面是同一机位）：
  1. 四分之三总览作封面，宽度不小于 1200 px；
  2. 人眼高度看研究对象的近景；
  3. 正立面或剖面；
  4. 带标注的 LOD 或变体对比条；
  5. 放在院落或城中的上下文图。

  每张配一句说明。
- **卡片文字分两层**（35 张）：summary、coverAlt、label 写给访客看，notes 写给工作流看。coverAlt 写「画面里看得到什么」；label 用「变体 · 用途档」格式；files 第一项放能代表作品的完整模型。内部用语（C级、CPU、负对照）不进 summary 和 coverAlt。「三分之四视图」这个笔误在 12 张城门卡里都有，要改。
- **派生登记表**（17 张组合卡）：组合卡列出所引用原件的文件和 SHA，写进 related。原件修好后，按表批量重建派生卡；城景点名的文件同步更新哈希。

### D. 与四层构件方案对齐

A 里的 1–6 条，都是「一个模板缺件，几十张卡跟着缺」。这正好说明构件层要先建起来。建议第一批构件是：
- 汉瓦屋面生成器（含收头）；
- 木构承托件；
- 门构件；
- 城门门台。

它们可以直接做进 `ly_style.py`（风格工具库，已在 S84、G10 上做到顶点级复刻）：改一处，你和 Claude 做的模型同时生效。固定的历史骨架（城池轮廓、有考据的城门、定制宫殿）不进随机生成。
