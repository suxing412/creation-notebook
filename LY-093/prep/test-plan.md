# LY-093 验收方案（可执行）

适用对象：一个批次 manifest 里选中的东北仓储武库包（LY-040 及其闭包 031–039）、作业场包（LY-060 及其闭包 051–059）、对外连接契约（LY-084）、地形差异片（LY-089）。和本批无关的区域记作"本批未纳入"，**不算通过**。

## 0. 运行方式（同一基线重放）

```
python -I prep/scripts/extract_rb.py D:/GitHub/creation-notebook-lab <scratch>/rb              # 只在需要审阅批分块时
python -I <batch>/make_config.py ...  -> qa/batch-<id>-config.json                               # 由 §1 生成，SHA 写死
D:/Blender/blender.exe -b --factory-startup --python-exit-code 1 -P prep/scripts/acc_replay.py -- \
    qa/batch-<id>-config.json qa/batch-<id>-result.json LAB=<lab>/docs RB=<scratch>/rb WP=D:/GitHub/creation-notebook-workpacks
```

- `acc_replay.py` 先逐个核对输入 SHA256，有一个不符就写 `status: SHA_MISMATCH` 并以退出码 1 结束，**不出任何结论**。
- 同一个配置文件同时含正例检查和负例；结果 JSON 记录配置自身的 SHA、Blender 版本、每个输入的实际 SHA。
- 改前基线：`prep/baseline-config.json`（`73999cbb…`）→ `prep/out/baseline-bce3211.json`。批次重放时，同一组检查在新基线上再跑一次，逐项对比"改前/改后"。
- **第二轮起用 v2**（v1 文件保留不动，作为可追溯的旧版本）：

```
python -I prep/scripts/make_config_v2.py D:/GitHub/creation-notebook-workpacks/LY-093/prep D:/GitHub/creation-notebook-workpacks   # 先核 v1 配置 SHA，再读 LY-006 registry
D:/Blender/blender.exe -b --factory-startup --python-exit-code 1 -P prep/scripts/acc_replay_v2.py -- \
    prep/baseline-config-v2.json prep/out/baseline-v2-bce3211.json LAB=<lab>/docs RB=<scratch>/rb WP=D:/GitHub/creation-notebook-workpacks

python -I D:/GitHub/creation-notebook-workpacks/LY-008/source/ly_check.py --json <out> lodset <LOD0> <LOD1> <LOD2>
python -I D:/GitHub/creation-notebook-workpacks/LY-008/source/ly_check.py --json <out> package <被验席位目录>
```

  v2 配置 `a3c0020f…`，结果 `out/baseline-v2-bce3211.json`（`d1a2208e…`），27 项检查、26 个负例。v2 的闸门除 GLB 外还核 5 个契约文件（LY-006 ports/zones/seams、LY-009 locks、LY-003 admission），契约变了同样拒跑。
- **重放自检（R1）**：每次换脚本版本，先在旧配置上跑一遍，与旧结果做"列表排序后逐字段相同"的比较；第二轮实测 40/40 相同。不相同就先查脚本，不能拿来判包。
- 只读：不写 lab，不存 .blend，不在输入旁边写文件。

组场景的规则：
1. 每个输入按 manifest 里的 SHA 绑定；路径用 `${LAB}`、`${WP}`、`${RB}` 占位，配置里不留本机路径。

3. 两仓几何只能出现一次：storage-main、v1 的 storage-group-organized、审阅批 granary_C_with_ground 三者互斥（C17 已证明后两者同一几何）。
4. 武库只用 LY-038 冻结的那一座（A 或 B）。

## 6. 结论格式（每批一份）

每个被验包给五项：完成产物、来源 SHA、未解决项、是否可接城、下一依赖。区域结论只能取四种之一：

- **局部通过**：列出路线、带宽、样本数、容差、负例全部检出；
- **局部通过，对外断开**：084 未放行时的预期结论；
- **阻断**：写明责任包、物件、三角对或样本坐标；
- **本批未纳入**。

不允许出现不带限定的"全城通行""物流完成""结构安全""历史成立"。CPU 渲染图写明是 CPU 图；没有浏览器/GPU 结果就写"未验"（LY-097 负责）。

## 7. 本方案的局限
