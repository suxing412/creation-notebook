# Luoyang browser verification

The PR workflow builds the same slimmed artifact as the Pages workflow, then tests it with Chromium on an ephemeral GitHub runner. It uses a read-only token, persists no checkout credentials, consumes no secrets, and does not deploy.

Coverage: first real WebGL render of the complete placed city; unchanged model membership and no scene rebuild or new model requests across all 41 planning zones and complete camera framing; animated and reduced-motion navigation; left drag, wheel, WASD, key release and focus loss; ground focus and compass; rapid choices; delayed research requests cancelled by manual controls and by zone selection; failed initial model load with same-page retry; independent research return; browser history return; left sidebar at desktop and 375px touch layout and orientation changes. Reports include screenshots, tested revisions, errors and history-cache evidence. BFCache is reported as restored only when the same document instance receives `pageshow.persisted`; a normal reload is recorded separately.

This is Chromium with SwiftShader and mobile emulation. Physical phones, hardware GPU performance and production deployment are separate checks. No screenshot, model load, camera state or app module is mocked. Recovery tests delay or fail actual model requests, then retry them. The rendered node list is read from real instantiated meshes; independent research assets are excluded from the city.

To run in an environment that permits browser/server startup, install the pinned package lock and Chromium, build `_site` using `lab/tools/assemble_site.py`, then run `npm test` in this directory. Do not bypass environment restrictions to run locally.

The installed-content cases verify the twelve delivered Z09/Z14/Yong variants via their exact HTTP byte counts and SHA-256 values, render each in the independent viewer, and select the two placed city nodes using real mouse hits on their geometry. The fixed-camera evidence toggle checks rendered image change and restoration. City default membership is 78; Z09-B remains independent. These cases do not claim automatic city LOD switching.

Desktop and mobile checks run as separate matrix jobs with separate artifacts. Neither suite skips tests or retries failures. The desktop job covers city, model publication and camera movement; the mobile job covers touch navigation and orientation changes.

The mobile input correction was verified by run 42252748113 (desktop 8/8 and mobile 1/1 on head 0d819da2). It uses the same touchscreen path for zone and overview taps, samples the 60px drag over multiple real-time steps, and requires fresh trusted events with a measured trajectory. Chromium traces and cancellation diagnostics remain attached. The earlier failure in run 42247087399 is preserved: debugger synthesizeTapGesture did not enter Aura's gesture recognizer, while a single-jump drag produced a 17,000px/s fling. This establishes normal sampled-drag behavior, not rapid flicks or physical-phone feel. Each later change must pass its own CI.

Camera-motion regression also checks screen-relative WASD before and after rotation, continuously held W with mouse drag and wheel, blur snapshots with no subsequent movement, near/far zoom limits, an out-and-back drag over a verified courtyard roof, and cancellation of a pending research load on blur. `node --test tests/navigation-motion.test.mjs` separately checks the actual motion helpers at 10–144 updates/second; these are mathematical checks, not GPU frame-rate measurements.

The camera uses time-based exponential smoothing of yaw/pitch and log-distance, and the exact integral of ground acceleration. OrbitControls remains the input parser, including wheel delta-mode normalization; its frame-based damping is disabled. References: https://threejs.org/docs/pages/OrbitControls.html , https://threejs.org/docs/pages/MathUtils.html , https://developer.mozilla.org/en-US/docs/Web/API/WheelEvent/deltaMode . Physical mouse, trackpad and phone feel still require user testing.
